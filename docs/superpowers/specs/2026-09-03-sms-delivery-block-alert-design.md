# 문자 수신차단 관리자 알림 설계

## 목적

간부·조립팀원·영업담당자에게 보낸 자동 문자의 Solapi 최종 전송결과를 확인하고, 수신거부 또는 차단으로 판단되는 결과가 나오면 관리자 `010-7731-4237`로 알린다.

## 검토한 방식

1. **5분 주기 조회(선택)**: 기존 Vercel Cron과 Solapi 인증 정보를 재사용한다. 알림이 최대 5분 늦을 수 있지만 공개 웹훅과 별도 등록 절차가 없어 배포·보안 위험이 가장 작다.
2. **Solapi SINGLE-REPORT 웹훅**: 거의 즉시 처리되지만 공개 수신 경로, 별도 비밀키, Solapi 계정의 웹훅 등록·운영이 추가된다.
3. **하루 1회 조회**: 가장 단순하지만 수신차단 확인이 늦어 운영 목적에 맞지 않는다.

## 선택한 동작

- `/api/cron/sms-delivery-monitor`를 5분마다 실행하며 기존 `CRON_SECRET` 인증을 사용한다.
- `notification_log`에서 `internal_*` 및 `chonbe_alert` 성공 접수 건만 조회한다.
- Solapi 메시지 목록 API에서 최종 상태를 받아 접수 성공과 실제 수신 완료를 구분해 저장한다.
- 상태 코드 `1061`, `2061`, `3061`, `3047`, `3054`, `3055`를 수신거부·착신거절·스팸차단 알림 대상으로 본다.
- 관리자 문자는 수신자명, 마스킹 번호, 원래 알림 종류, 상태 코드와 사유, 확인 시각을 포함한다.
- 같은 수신자·같은 상태 코드·같은 KST 날짜의 관리자 알림은 한 번만 보낸다.
- 관리자 알림 자체와 고객 알림은 감시 대상에서 제외해 재귀 발송을 막는다.
- 주말에는 관리자 문자를 보내지 않고, 다음 평일 실행에서 미처리 결과를 다시 확인한다.

## 저장과 실패 처리

- 기존 발송 로그에 최종 상태 코드·사유·처리 시각·수신 시각을 저장한다.
- 별도 관리자 알림 테이블에서 원자적으로 중복을 선점한다.
- 관리자 문자 발송이 실패하면 실패 상태를 남기고 다음 평일 실행에서 재시도한다.
- Solapi 조회 실패는 기존 발송 성공 기록을 변경하지 않고 다음 실행에서 재시도한다.

## 한계

휴대전화 자체 차단이나 스팸 앱이 통신사에 성공으로 보고되는 경우에는 감지할 수 없다. 이 기능은 Solapi가 반환하는 최종 상태만 근거로 알린다.

## 검증

- 인증 실패 시 외부 조회와 발송이 일어나지 않는지 확인한다.
- 수신완료 `4000`은 저장만 하고 관리자 문자를 보내지 않는지 확인한다.
- 지정 차단 코드는 관리자에게 한 번만 전송되는지 확인한다.
- 관리자 문자와 고객 문자는 감시 대상에서 제외되는지 확인한다.
- 발송 실패 후 다음 실행에서 재시도되는지 확인한다.
- 배포 후 Cron 등록, 운영 커밋, 첫 실행의 최종상태 저장을 확인한다.
